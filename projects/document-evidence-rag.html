PROJECT 01 · DOCUMENT INTELLIGENCE

DocTrace
复杂文档多模态检索

面向扫描件、多栏排版、复杂表格、图表和公式，完成从 PDF 解析到 TopK 证据召回的工程链路。重点不是让模型覆盖原结果，而是保留来源、显式处理冲突，并让每条召回证据可回到原页复核。

PythonMinerUQwen3-VLMySQLMilvusHybrid Search
当前项目边界

系统返回带出处的检索证据，暂不包含最终自然语言答案生成器。

01 / PROBLEM

复杂 PDF 的问题不止是 OCR

内容缺失

解析器可能完全漏掉文字，也可能与 PDF 文本层在数字、脚注或段落边界上冲突。

结构失真

双栏、旋转页、页眉页脚和标题层级会改变阅读顺序，直接污染下游 Chunk。

表格复杂

多级表头、超长表、跨页表和被误识别为图片的表格，需要不同于正文的处理策略。

证据风险

VLM 能补全视觉信息，但输出并非真值；冲突结果不能无记录地覆盖原始内容。

02 / ARCHITECTURE

从文件输入到可追溯召回

  1. 01
    PDF 预检

    文件完整性、页数、旋转与运行身份

  2. 02
    基础解析

    MinerU 输出 Page / Block / Asset

  3. 03
    完整性审计

    文本层、坐标与可见墨迹交叉检查

  4. 04
    按需视觉修订

    疑难文字、表格、图表与公式路由

  5. 05
    结构重建

    阅读顺序、标题路径与跨页表判断

  6. 06
    多模态切块

    正文、表格、图表和公式分层生成

  7. 07
    证据召回

    MySQL 存证，Milvus 混合检索与重排

证据链每一步都保留来源与状态
raw content→revisions→resolved / review→verified / provisional chunk→page · bbox · asset
03 / ENGINEERING DECISIONS

关键设计决策

01

非破坏式证据裁决

MinerU 原始内容永久保留，PDF 文本层与 Qwen 输出作为独立修订。只有证据满足规则时才进入 resolved；发生冲突时保留主证据并标记待复核。

02

局部、按需调用 VLM

先用确定性规则发现乱码、模糊、旋转、表格异常等问题，再为不同 Block 路由专用任务。不可读区域禁止根据上下文猜测。

03

复杂表格双源验证

按真实行边界切片并重复表头，将 MinerU 与 Qwen 结果展开为 canonical cells 逐格比较；不同表号和表题是跨页合并的硬否决条件。

04

检索粒度与风险分层

表格同时生成摘要、行组和精确单行，图表拆分整体描述与事实。Chunk 区分 verified 与 provisional，召回结果携带页码、bbox、资产和证据状态。

04 / VALIDATION

验证结果与适用边界

代表性文档召回回归

回归集覆盖事实定位、表格字段、跨页证据和图表信息，并分别检查页命中、内容命中与来源可追溯性。

验证范围是当前代表性文档的证据召回，不代表通用 OCR、跨文档检索或最终答案准确率。
  • Chunk 结构、去重与页码连续性检查纳入自动化回归
  • 阅读顺序、表格重建与证据状态均有对应测试
  • 冲突内容以 provisional 证据保留，不伪装为已确认结果
  • 当前词法索引适合单文档规模，MySQL 与 Milvus 尚无分布式事务
