文档处理Chunk检索验证

PROJECT 01 · DOCUMENT INTELLIGENCE

复杂文档解析与证据检索

实习项目太极计算机股份有限公司2026.01—2026.07

针对扫描件、双栏、复杂表格、图表和公式 PDF，系统先审计 MinerU 是否漏解析或错序，再按问题类型调用 VLM 修复；完成结构重建和分模态切块后，通过问题分流、Dense + 词法候选与 Rerank 返回带页码、坐标和来源的证据。

技术栈：Python、MinerU、Qwen3-VL、FastAPI、OpenCV、pypdf、MySQL、Milvus、Qwen3-Embedding、BM25 / 词法检索、Rerank

01 / SYSTEM

两条主链

DOCUMENT PATH

文档进入系统

PDF → MinerU → 页级审计 → VLM 修订 → 结构重建 → Chunk → 索引

EVIDENCE PATH

证据持续留痕

raw content → revisions → resolved / review → verified / provisional

QUERY PATH

问题进入系统

fast / rewrite / bypass → 多查询召回 → RRF → Rerank → Top-K

MySQL 保存页面、资产、Block 和全部 Revision，Milvus 只承载检索需要的 Chunk 元数据与向量；解析事实层与检索索引分开维护。

02 / INGEST

从 PDF 到可索引证据

  1. 01
    PDF 预检

    校验文件与加密状态，记录页尺寸、旋转角和 SHA-256 文档身份。

  2. 02
    MinerU 解析

    上传完整 PDF，取得 content_list、版面块和图片资产；ZIP 解压前检查路径穿越。

  3. 03
    统一证据图

    把 Page、Block、Asset、Revision 归一化，保留 MinerU 原始顺序与原始内容。

  4. 04
    页级反向审计

    用 PDF 文本层、bbox 与可见墨迹检查漏块、数字差异、脚注冲突和遮挡区域。

  5. 05
    VLM 定向修复

    只将命中质量 Flag 的文字、表格、图表和公式路由到对应视觉任务。

  6. 06
    结构重建

    重新计算分栏阅读顺序、标题树、表格上下文和跨页表关系。

  7. 07
    多模态 Chunk

    正文、表格、图表、公式按不同粒度生成 verified / provisional 检索单元。

  8. 08
    质量门控与索引

    Chunk 审计通过后批量 Embedding，写入 MySQL 证据图与 Milvus 向量索引。

03 / QUALITY GATE

先定位问题，再调用模型

质量门控按问题 Flag 决定处理分支。已有可靠证据时不重复调用 VLM；单个视觉任务失败只影响对应 Block，并写入错误类型、请求信息和耗时。

解析质量门控
问题如何发现处理方式
完全漏块PDF 文本层行 + bbox 覆盖 + 局部可见墨迹可靠文本层补偿 Block；证据不足时进入复核
文字或数字冲突序列相似度、字符 F1、数字与脚注编码比对保留 MinerU 主证据，修订作为独立 Revision
低清 / 低对比Laplacian 方差与灰度标准差原图和增强图共同输入 VLM，并记录不确定项
遮挡区域深色实心区域占比标记 unreadable，禁止模型根据上下文猜测
复杂或跨页表结构区域、行分隔线、表号 / 表题 / 表头与页边位置完整行切片、双源逐格核对；身份冲突直接禁止合并
文字裁决原则

MinerU 非空时作为 primary evidence。VLM 与其一致或只做可验证的非破坏补充才写入 resolved；事实字符冲突时保留原文并标记 review，不让模型输出静默覆盖解析结果。

04 / TABLES

复杂表格的双源核对

  1. 1
    识别结构区域

    先识别方向、表题、表头、数据区、日期、单位和脚注；再依据真实行分隔线修正数据边界。

  2. 2
    按完整行切片

    每个 tile 重复表头，相邻片重叠一整行；合并时只消除重叠行，避免固定像素切到数据行中间。

  3. 3
    Canonical Cells

    把 MinerU HTML 与 Qwen 结果展开为二维单元格网格，按 row / column 比较数字、负号、小数和百分比。

  4. 4
    跨页身份门控

    只有“上页表到底、下页表从页顶开始”才进入判断；不同表号或明显不同表题是硬否决，不能被 Embedding 或 VLM 推翻。

05 / CHUNK

按内容类型组织检索粒度

多模态 Chunk 设计
内容切分与上下文Chunk Role
正文同章节、同栏、同状态的相邻 Block；优先在段落和完整句边界切分text_segment
表格展开 rowspan / colspan，重复表题、单位和多级表头，同时保留行级 cellstable_summary / row_group / row
图表 / 图片生成整体结构摘要，再拆出包含数值、趋势或极值的局部事实chart_summary / chart_fact / image_summary
公式把同页同章节的前文末段、LaTeX 与后文首段组合，避免公式脱离语境formula_context
每条 Chunk：source blocks+page / bbox+asset+section path+parent / sibling+retrieval tier

索引前执行结构硬门控：检查 ID、正文、来源页、坐标、顺序、父子关系、重复文本和证据等级。出现 hard failure 时停止 Embedding，不替换线上索引。

06 / QUERY ROUTING

明确问题直接查，模糊问题再改写

FAST

明确问题

包含明确页码、表号、图号，或实体和提问目标完整。直接进入检索，不调用改写模型。

REWRITE

上下文追问

过短、口语化或包含“这两个、那一列”等指代。结合有界上一轮上下文生成独立查询。

BYPASS

非检索输入

闲聊、致谢和对话控制指令不访问向量库，也不产生无意义的检索调用。

改写安全约束

  • 固定 JSON Schema、temperature=0；改写只能使用当前问题和有界上下文。
  • 程序检查新增数字、年份和表号，发现凭空增加的信息就丢弃该改写。
  • 原问题始终保留；改写只扩充候选，不能替换用户原始问题。
07 / RETRIEVAL

多查询候选融合与一次重排

01批量 Query Embedding→02Dense + 中文 bigram 词法候选→03RRF 合并候选并集→04候选并集一次 Rerank→05按 logical parent 控制重复
  • 每条改写查询分别取得 Dense 与词法候选，多条查询一次批量 Embedding，不重复跑完整 Rerank。
  • 词法侧保留英文、数字、小数和百分比，中文按字符 bigram；对表格摘要做轻度长度归一。
  • 表格同一 parent 最多保留 3 条行证据，其他 parent 最多 2 条，兼顾多行问题和结果多样性。
08 / VALIDATION

评测结果

88% → 97%+通过页级漏检检查、跨页表合并和定向 VLM 后处理提升解析准确率。
Top3 +20%+分模态 Chunk 配合向量、关键词与 Rerank 混合召回后的证据召回提升。
关键词覆盖 +30%+针对多轮问答的指代不清问题，经路由与上下文重写后的简历口径结果。
